изменение только в этой одной строке.

Сделать своими силами SQL-экспорт вместо `pg_dump` — прямо против условия

Сеть режет политика окружения сессии. Её можно расширить: меню облачного
окружения в заголовке сессии → Edit → Network access (уровень доступа либо
добавление хоста в список разрешённых). Уровни описаны в
https://code.claude.com/docs/en/claude-code-on-the-web

Пока этого нет — шаги 6–8 и restore verification выполняются **с вашей машины**.

## Что подготовлено взамен

`scripts/backup/backup_and_verify.sh` — весь утверждённый план одной командой:

```bash
export DB_URL='postgresql://postgres.kmvsjozxjosmkhvphzdz@<POOLER_HOST>:5432/postgres?sslmode=require'
read -rsp 'DB password: ' PGPASSWORD; export PGPASSWORD; echo
bash scripts/backup/backup_and_verify.sh
```

Делает: предполётную проверку заморозки → снимает **ожидаемые значения с живого
production** → `pg_dump -Fc --compress=9` (`public` + `supabase_migrations`) →
метаданные (`backup_started_at`, `backup_completed_at`, размер, SHA-256, источник
с затёртым паролем, версии сервера и `pg_dump`) → поднимает одноразовый
PostgreSQL 17 в Docker с ролями Supabase и заглушкой `auth.uid()` → восстанавливает →
сверяет **27 показателей**: структуру (tables, views, functions, triggers, indexes,
constraints, policies, sequences, migration metadata), финансовый baseline
(включая FIN-03 и `opening_balance`) и security baseline (ACL шести критических
функций плюс `md5(pg_get_functiondef)`) → применяет 0086–0092 на копии →
повторяет сверку и прогоняет `db_integrity_audit.sql`.

Ожидаемые значения **не зашиты в скрипт**, а снимаются с production в момент
запуска — сверка не устареет вместе с baseline, что особенно важно после
сегодняшнего сдвига. Пароль берётся из `PGPASSWORD`, в отчёт и в лог не попадает;
каталог артефактов вне репозитория, `chmod 700`.
