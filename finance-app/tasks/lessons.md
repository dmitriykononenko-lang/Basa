# Уроки (читать перед работой, дополнять после каждой правки от владельца)

- **Хост пулера бери из истории/дашборда, не из примеров.** Проект на `aws-1-eu-central-1`;
  с `aws-0` пулер отвечает `tenant/user not found`. Сетевые проверки делай против того же хоста.
- **Обрывы VPN — норма.** Любой скрипт, который ходит в production, повторяет запросы
  (до 6 раз), но при `password authentication failed` останавливается сразу (бан в пулере).
- **pg_safeupdate есть только в production.** Репетиция на локальной копии не ловит
  `UPDATE requires a WHERE clause` — всегда репетируй на production внутри откатываемой транзакции.
- **Новые функции = EXECUTE у anon по умолчанию.** После каждой миграции с функциями проверяй
  `has_function_privilege('anon', …)`.
- **Откат миграции пишется против текущего production, а не против исходника.** 0091_down
  возвращал старые уязвимые тела `can_*`, хотя в production уже стоял hotfix; 0092_down удалял
  представление, которое существовало до 0092. Сверяй откат с дампом.
- **Не удаляй файл, который только что проверен, без отдельной проверки замены.** Скрипт
  `rm -f … && age -p …` уничтожил рабочий `.age`, а владелец параллельно удалил открытый дамп.
  Сначала создай новый файл под другим именем, проверь, потом удаляй старый.
- **Строка ввода чата не интерактивна.** Команды с паролем (`read -rs`, `age -p`) запускай во
  вкладке терминала (`run_in_terminal`) и говори владельцу вводить там.
- **Снимки показателей во время работающего импорта вводят в заблуждение.** Дождись конца
  прогона (последний `created_at`), прежде чем делать выводы о «лишних» строках.
- **Перед любой работой с данными — объясни все изменения с прошлого снимка.** Другие сессии и
  сам владелец меняют production (сверка 0095 обнулила `opening_balance`).
