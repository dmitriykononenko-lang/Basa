## 2. Отклонение от пункта 6 и принятое вами решение

Vercel отказал: `403 Additional permissions are required to create production
environment variables` (тот же класс, что прежний 403 на листинг env).

По вашему выбору замок держится **кодом**: в `maintenance.ts` появилась именованная
константа `LOCK_DEFAULT = true` — она определяет поведение **только при
отсутствующей переменной**. Семантика самой переменной осталась утверждённой и
остаётся главной:

```ts
const LOCK_DEFAULT = true;
const OFF = new Set(["false", "0", "no", "off"]);

export function financialImportsLocked(): boolean {
  const raw = (process.env.FINANCIAL_IMPORTS_DISABLED ?? "").trim().toLowerCase();
  if (raw === "") return LOCK_DEFAULT;   // переменной нет — решает код
  if (OFF.has(raw)) return false;        // явное выключение
  return true;                           // true/1/yes/on и любое иное значение
}
```

Тот же модуль **добавлен и в ветку PR #99** — иначе деплой PR #99 снял бы замок.
Снятие замка теперь = отдельный коммит `LOCK_DEFAULT = false` + отдельный деплой,
то есть осознанный контролируемый шаг, как вы и планировали.

## 5. `last_synced_at` — разбор

Деплой стал READY в **08:22:44**, отметка сдвинулась в **08:26:54**, то есть через
4 минуты после включения замка. Импорта при этом не было: `transactions`,
`import_batches` и `tochka_sync_log` не изменились.

Две гипотезы, обе без записи финансовых данных:

* **H1 — авто-синк на СТАРОЙ сборке, начатый до переключения alias.** Маршрут пишет
  отметку дважды: перед импортом (строка 40) и после (строка 77). Запрос, начатый
  около 08:20 на прежнем деплое, мог закончиться в 08:26:54, не найдя новых операций.
  Косвенно подтверждается тем, что в эти же минуты в приложении явно работал человек
  (§7). Не сходится одно: значение имеет ровно **.000000** микросекунд, а колонка —
  `timestamptz(6)` без округления, тогда как `new Date().toISOString()` даёт
  миллисекунды (вероятность ровного значения ~1/1000).
* **H2 — прямая запись мимо приложения** (SQL-редактор, табличный редактор Supabase,
  локальный запуск с боевыми ключами). Объясняет ровную секунду.

Достоверно различить их не смог: runtime-логи прежнего деплоя за этот период
Vercel уже не отдаёт (на текущем плане они живут недолго), поэтому «логов нет» —
не доказательство отсутствия запроса. **Я этой записи не делал.** Скажите,
пожалуйста, не правили ли вы (или кто-то из команды) эту строку напрямую.

Практического риска сдвиг не несёт: он двигает отметку **вперёд**, из-за чего
собственный 120-минутный тротлинг приложения срабатывает реже, а guard теперь
блокирует импорт независимо от тротлинга.

## 8. Главное ограничение, которое надо зафиксировать

Замок закрывает **контур банковского импорта**, и эту задачу он решает: новые
банковские операции в production попасть не могут ни через открытие приложения
сотрудником, ни через Vercel cron, ни через pg_cron.

Но он **не** блокирует обычные ручные финансовые правки, и события 08:29 и 08:31
показывают, что люди в приложении продолжают работать. Значит:

* baseline и дальше будет смещаться от ручной работы;
* окно «backup → миграции» по-прежнему требует **организационной** договорённости,
  иначе дамп перестанет быть точкой возврата к моменту старта 0086.

Расширять замок на весь пользовательский ввод я не стал: это выходит за рамки
Разрешения №ML-1 и остановило бы работу компании целиком.
