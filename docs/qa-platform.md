# QA-задание: полное тестирование платформы Basa (finance-app)

## 0. Контекст для тестировщика

**Что это.** Внутренняя финансово-учётная платформа агентства Koagency: учёт
доходов/расходов/переводов по счетам, разнесение по статьям и проектам, контрагенты,
сотрудники и зарплаты/бонусы, займы, лицензии, отчёты (P&L, ДДС), база знаний, академия,
импорт банковской выписки из банка «Точка».

**Стек/особенности, влияющие на проверки:**
- **Деньги хранятся в копейках** (×100). В крипте USDT тоже ×100, конвертация по курсу
  **80 ₽/USDT**. Проверяй, что на экранах суммы делятся на 100 и не «разъезжаются» на копейках.
- **Мультикоманда + RLS.** Все данные привязаны к команде (team). Пользователь видит только
  свою команду. Права на изменение финансов — у `owner/admin/manager`; `employee` — ограниченно;
  `viewer` — только чтение.
- **Интеграция с «Точкой».** Импорт выписки: сопоставление контрагента по ИНН/имени,
  назначение платежа → `note`, признак источника `source='tochka'`.
- **Окружения/доступы:** прод или стейдж приложения; для интеграций нужны тестовые ключи
  (Точка — read-only). Курсы валют — через `/api/cbr`.

**Стек:** Next.js 14 (App Router) + Supabase (Postgres/RLS) + Tailwind; графики recharts;
редактор базы знаний на TipTap; `sanitize-html`. Автотестов в репозитории нет → это **ручное QA**.

**Нужные учётные записи (одна команда, разные роли):** `owner`, `manager`, `employee`,
`viewer`. Плюс **вторая команда** (другой пользователь) — для проверки изоляции данных.

**Как фиксировать баг:** модуль → шаги воспроизведения → ожидаемое/фактическое → скрин/видео →
(для данных) SQL-вывод → роль/учётка → severity (blocker/major/minor).

## 1. Сквозные проверки (cross-cutting)

**1.1 Аутентификация:** `/login` (вход), `/join` (по инвайту), `/auth/reset` (сброс пароля),
`/auth/callback`.
- ✅ Вход/выход, неверный пароль — понятная ошибка; сброс пароля по письму; протухший/чужой
  инвайт — отказ.
- ✅ Неавторизованный пользователь на `(app)/*` редиректится на `/login` (middleware).

**1.2 Роли и доступ (повторить ключевые экраны под каждой ролью):**
- `viewer` — всё только на чтение: нет кнопок создать/редактировать/удалить; прямые
  POST/PUT/DELETE отклоняются БД (RLS).
- `employee` — видит свою карточку/выплаты, но не управляет чужими финансами.
- `manager/owner` — полный доступ к финансам.
- ✅ Эскалации нет: `viewer`/`employee` не может изменить данные ни через UI, ни прямым запросом.

**1.3 Изоляция команд (RLS):** под пользователем команды B попытаться открыть сущности команды A
(по прямым ссылкам/ID).
- ✅ Данные другой команды недоступны (пусто/403), утечки нет.

**1.4 Общие UI:** тёмная/светлая тема, мобильная вёрстка ключевых экранов, пустые состояния
(«нет данных»), пагинация больших списков, локаль и формат чисел/дат (₽, разряды).

## 2. Финансовое ядро

**2.1 Счета `/accounts`:** создать/редактировать/архивировать счёт; валюта; баланс
пересчитывается из операций. ✅ Баланс = Σ доходов − Σ расходов ± переводы.

**2.2 Операции `/transactions`:** создать доход/расход/перевод; фильтры
(дата/тип/счёт/контрагент/проект/статья); редактирование/удаление; импорт-метки (`source`).
- ✅ Перевод между счетами не двоит суммы (уходит с одного, приходит на другой; в P&L не
  учитывается как доход/расход).

**2.3 Распределение статей `/transactions/categorize`:** см. блок 7 (фича внешних ID). Базово:
проставление статьи по одной, подсказки по контрагенту, автораспределение.

**2.4 Сортировка/массовые действия `/transactions/sort`:** массовая простановка статьи/проекта.
✅ Применяется только к выбранным; счётчик корректен.

**2.5 Статьи `/categories`:** доходные/расходные; архив; нельзя сломать существующие операции
при архивации.

**2.6 Проекты `/projects`, `/projects/[id]`:** создать; ответственный аналитик/менеджер; бонус
проекта; даты/статус; в карточке — доходы/расходы/прибыль по проекту. ✅ Прибыль =
доходы−расходы по операциям с этим `project_id`.

**2.7 Контрагенты `/counterparties`, `/counterparties/[id]`:** CRUD; роли
(клиент/поставщик/агент/сотрудник, несколько сразу); ИНН/КПП/контакты; поиск дублей
(`DuplicateSuggestions`). ✅ Слияние/пометка дублей не теряет операции.

**2.8 Бюджеты `/budgets` и регулярные `/recurring`:** план vs факт; повторяющиеся операции
генерируются по расписанию. ✅ Регуляр не создаёт дубликаты.

## 3. Зарплаты, бонусы, сотрудники

**3.1 Сотрудники `/employees`, `/employees/[id]`:** карточка, оклад, выплаты, история.
**3.2 Зарплата `/payroll` + `/settings/motivation`:** начисления оклада и **бонусов**.
- ⚠️ **Регресс-кейс:** бонус НЕ должен начисляться дважды (был баг двойного начисления —
  «базовый бонус» + «начисление за сделку»). Проверить, что по сотруднику/проекту бонус
  считается один раз.
**3.3 Агенты `/agents`, `/agents/[id]/report`:** вознаграждение агента, отчёт по приведённым
клиентам.

---

## 4. Займы, лицензии, долги

**4.1 Долги/займы `/debts`:** выдача/возврат займа (в т.ч. беспроцентный), займы под выплату
ЗП; приход/расход корректно влияет на баланс.
**4.2 Лицензии `/licenses`:** учёт лицензий (Radist/amoCRM/Wazzup) по проектам/клиентам —
соответствует разнесённым расходам (см. блок 8).

## 5. Отчёты и дашборд

**5.1 Дашборд `/dashboard`:** сводные показатели, графики (recharts). ✅ Цифры сходятся с
операциями; смена периода пересчитывает.
**5.2 P&L `/reports/pnl`:** доходы−расходы по периодам/статьям; переводы исключены; крипта по
курсу 80 ₽.
**5.3 ДДС/Cashflow `/reports/cashflow`:** движение по счетам; остатки на начало/конец.
**5.4 Академия-отчёт `/reports/academy`.**
- ✅ Во всех отчётах суммы из копеек переведены в рубли; итоги не «прыгают» на копейках.

## 6. Контент-модули

**6.1 База знаний `/knowledge-base` (+ departments, new, [id]/edit):** редактор TipTap,
картинки/ссылки, разделы.
- ⚠️ **Безопасность (XSS):** вставить в статью HTML/скрипт — должен быть **очищен**
  `sanitize-html`, скрипт не исполняется.
**6.2 Академия `/academy` (+ new, [id], edit, certificate):** курсы, прохождение, **сертификат**
(генерация/просмотр).
**6.3 Календарь `/calendar`:** события/дедлайны.
**6.4 Сейф `/vault` (+ `/api/vault/[id]/reveal`):** хранение секретов.
- ⚠️ **Безопасность:** «показать секрет» доступно только уполномоченной роли; `viewer` не может
  вызвать `reveal`; значение не утекает в логи/URL.

## 7. Фича «Внешние ID» + подсказка проектов (новое)

**7.1 Карточка контрагента:** секция «Внешние ID» — добавить/изменить/удалить строки
(система amoCRM/Radist/Wazzup/Другое + ID + опц. проект); несколько ID на клиента; защита от
дублей `(контрагент, система, ID)`; сохраняется в Add и Edit формах; `viewer` не редактирует.
**7.2 Распределение статей:** операция с `ID <cid>` в назначении → чип **«✨ Проект»**; фолбэк по
доминирующему проекту контрагента; кнопка **«Привязать проекты (N)»**; это **предложение, не
авто**.
**7.3 Удаление проекта**, на который ссылается внешний ID → `project_id` у ID становится NULL
(`on delete set null`), без падения.

> Детальные тест-кейсы по этой фиче — в `docs/qa-external-ids.md` (при наличии).

## 8. Интеграции

**8.1 Точка `/settings/bank`, `/transactions/import` + `/api/tochka/*`:** подключение
(`connect`/`test`), импорт выписки (`import`), маппинг (`mapping`), подсказки (`suggest`), крон
(`cron`).
- ✅ Контрагент сопоставляется по ИНН/имени; назначение → `note`; повторный импорт **не
  дублирует** операции (идемпотентность по `external_id`/реквизитам).
- ⚠️ Ключи банка — **read-only**; секреты не светятся в UI/логах.
**8.2 Курсы ЦБ `/api/cbr`:** валютные операции пересчитываются по актуальному курсу;
недоступность API — graceful (не падает).

---

## 9. Регресс по данным (если есть доступ к БД)

- **Разнесение Radist:** лицензионные расходы имеют проект; итоги выручки/расходов **не
  изменились** после простановки `project_id` (менялся только проект, не суммы).
- **Бонусы:** нет двойных начислений.
- **Переводы:** не учитываются как доход/расход в P&L.
- **Копейки:** выборочно сверить 10 операций — `amount/100` = сумма на экране.

---

## 10. Нефункциональное

- **Производительность:** списки операций/контрагентов на больших объёмах (пагинация, отклик
  < ~1–2 c).
- **Ошибкоустойчивость:** обрыв сети при сохранении — понятная ошибка, нет «полусохранённых»
  данных.
- **Доступность:** навигация с клавиатуры по ключевым формам; контраст в тёмной теме.
- **Браузеры:** Chrome/Firefox/Safari + мобильный.
